# Требования MVP

Поведение продукта. Рамки и «не делаем» — [3-constraints.md](3-constraints.md). Срез работ — [6-iterations.md](6-iterations.md).

Веб-тренажёр словарного запаса. Родной язык — русский. Изучаемые языки — английский и французский. Направление тренировки: иностранный ↔ русский.

Несколько пользователей с входом по логину и паролю. Словарь общий, прогресс личный.

## Экраны

0. Вход (логин / пароль)
1. Фильтр
2. Тренировка (карточки)
3. Итог сессии
4. Сводка (прогресс и нагрузка)
5. Оценка знаний (триаж знакомых слов)

Вёрстка адаптивная: одни и те же экраны на смартфоне и на компьютере.

## Пользователи и вход

### Кто

- Несколько **учеников** (семья или небольшая группа). Все с одинаковыми правами: тренировка, оценка, сводка.
- Ролей admin/teacher в UI **нет**. Создание и сброс паролей — скриптом на сервере.
- Публичной саморегистрации **нет** (инстанс может быть в сети).

### Аккаунт

- Уникальный `login` (латиница/цифры/`_`/`-`, без пробелов).
- Пароль хранится только как hash (argon2 или bcrypt).
- Опционально `display_name` для шапки (если пусто — показывать login).

### Экраны и поток

- Неавторизованный запрос к тренировке / оценке / сводке / API сессии → редирект на **/login**.
- **/login**: поля логин и пароль, кнопка «Войти». Ошибка при неверных данных — без уточнения, какое поле неверно.
- После входа — фильтр `/`. В шапке: кто вошёл + **«Выйти»**.
- Выход сбрасывает сессию авторизации и cookie тренировки.
- Смена пароля в UI в этой волне **не нужна** (скрипт `set_password`). Позже — по желанию.

### Создание пользователей

- CLI, например: `python scripts/create_user.py --login anna --password '…'`.
- При первом деплое после миграции: создать пользователя и **приписать** существующие `card_progress` / `card_reviews` ему (если прогресс ещё без `user_id`).

### Изоляция данных

| Данные | Область |
|---|---|
| `entries` и метки | общие на весь инстанс |
| `card_progress` | только свой `user_id` |
| `card_reviews` | только свой `user_id` |
| лимит новых за день | считается по своему прогрессу |
| сводка / due / оценка | только свои цифры |

Чужой прогресс недоступен: нет экрана «ученики», нет API «по user_id».

### Сессия

- После логина — server-side session (или signed cookie) с `user_id`, httpOnly, SameSite=Lax.
- Cookie очереди тренировки/оценки привязана к авторизованному пользователю; чужую сессию не продолжать.

## Фильтр

Перед стартом обязательно выбрать язык (`en` или `fr`).

Учебник обязателен: если не отмечен ни один, в фильтре 0 слов и тренировка не стартует. Темы (и уровень) необязательны, темы выбираются внутри учебника и только при его отметке; у учебника есть чип «Без темы». Подробности — [решение 017](4-decisions.md).

На фильтре показывать оценку очереди для выбранного языка: сколько **due**, сколько новых ещё можно ввести сегодня, сколько карточек ещё без прогресса.

С фильтра — два режима: **Тренировка** и **Оценка знаний**.

## Оценка знаний

Отдельный режим (не смешивать с дневной due-сессией). Цель — не жечь дневную квоту новых на уже знакомые слова из учебников.

- Берёт только карточки **без** `card_progress` (оба направления отдельно).
- Пачка до **40** карточек за сессию (фильтр тот же).
- Ход: лицо → переворот → три кнопки:
  - **Знаю** → interval 7, due = сегодня + 7 (сеет FSRS Review); **не считается** в дневную квоту новых;
  - **Сомневаюсь** → interval 1, due = завтра, без квоты новых;
  - **Не знаю** → то же (interval 1, due завтра), без квоты новых.
- Без requeue внутри сессии оценки.
- `introduced_via = assess` / `source = assess` — чтобы сводка и лимит новых смотрели только на тренировочные вводы.
- Итог: знаю / сомневаюсь / не знаю / длительность.

## Сессия

- Очередь дня: все **due** по фильтру, затем порция **новых** до дневного лимита.
- Лимит новых **разный по языку** (сейчас: EN **10**, FR **20**). Квоты независимы. Учебник/тема только режут пул.
- Внутри due и новых — **приоритет направления**: EN сначала RU→EN (`native_to_foreign`), FR сначала FR→RU (`foreign_to_native`); второе направление следом. Оценка знаний — тот же bias.
- Если due и доступных новых нет — сессию не начинать.
- Направления оба в сессии (не отключаем второе), только порядок.
- Карточка = единица + направление: знать EN→RU не значит знать RU→EN.
- Ход: лицо → переворот → **Снова / Трудно / Хорошо / Легко** → следующая карточка.
- «Завершить» обрывает сессию; оставшиеся due остаются на потом.

## Итог сессии

Показать:

- для тренировки: снова / трудно / хорошо / легко;
- для оценки: знаю / сомневаюсь / не знаю;
- длительность;
- время сессии.

## Единица словаря

Слово, выражение или фраза.

Хранить в том виде, в котором занесли. Глаголы — в инфинитиве.

## Поля карточки

- иностранная форма;
- часть речи: существительное, прилагательное, глагол, местоимение, числительное, наречие, фраза, другое;
- род (`m` / `f`) — необязательно; для французских существительных;
- транскрипция только у иностранной формы (русскому не нужна);
- один или несколько переводов на русский.

## Лицо и оборот

Лицо — вопрос плюс подсказка.

- Иностранный → русский: иностранная форма (+ для FR noun с родом — артикль `le`/`la`/`les` только в отображении) + часть речи + род (если есть) + транскрипция.
- Русский → иностранный: перевод(ы) + часть речи; транскрипции, рода и артикля нет (иначе подсказка ответа).

Оборот — недостающие поля: перевод(ы) либо иностранная форма (с артиклем для FR noun) с родом и транскрипцией.

## Группировка

- Язык: `en` | `fr` (обязателен).
- Уровень: один, `A1` | `A2` | `B1` | `B2`, можно не задавать.
- Темы: метки, сколько угодно, можно пусто (одежда, семья и т.д.).
- Учебники: метки, сколько угодно, можно пусто (Starlight 7, Starlight 6, Loiseau Blue 5 и т.д.).

## Повтор (FSRS)

Четыре кнопки тренировки: **Снова / Трудно / Хорошо / Легко** (FSRS Again/Hard/Good/Easy). Детали: [12-fsrs.md](12-fsrs.md), [10-anki.md](10-anki.md) — прежний алгоритм.

У каждой карточки (единица × направление): `due_on`, `interval_days` (для сводки), `stability`, `difficulty`, `fsrs_state`, `last_review`, `introduced_on`, `introduced_via` (`train` | `assess`). Нет строки прогресса = новая карточка.

- Планировщик: пакет `fsrs`, retention 90%, fuzz вкл, due в **календарных днях**.
- **Снова** → due по FSRS + карточка **в конец текущей сессии**.
- Сессия: все due по фильтру, затем новые до дневной квоты языка (EN 10 / FR 20).
- Оценка знаний — отдельный триаж (Знаю → 7д, Сомневаюсь/Не знаю → завтра), без FSRS на первом вводе; дальше train по FSRS.

Прогресс хранится отдельно по направлению и не смешивается с текстом карточки.

## Сводка

Цель — понять прогресс по корпусу и решить: **усилить / оставить / снизить** дневную нагрузку (лимит новых).

Вход: язык обязателен; учебник в первой версии не обязателен (можно добавить позже). Ссылка на сводку — с фильтра / шапки.

### Горизонт

Оценка времени на **оставшийся объём новых карточек** (единица × направление без прогресса):

- при текущем лимите новых в день (календарные дни, каждый день занимаетесь);
- по фактическому темпу ввода новых за последние 7 дней;
- грубо «первый показ всего + ~21 день» — когда последние карточки могут дойти до interval ≥ 21.

Это не «всё выучено навсегда»: после ввода новых due-повторы продолжаются. Цель метрики — понять масштаб недель/месяцев и эффект смены лимита.

### Корпус

Показать по выбранному языку:

- всего карточек (единица × направление);
- новых (ещё без прогресса);
- уже в системе интервалов;
- доля с `interval_days ≥ 7` и `≥ 21` («осело»).

### Нагрузка (7 и 30 дней)

- due на сегодня;
- прогноз due на завтра и через 3 дня (по текущим `due_on`);
- сколько новых введено за день / к лимиту языка (EN 10 / FR 20);
- медиана отвеченных карточек в день;
- были ли дни с незакрытым хвостом due (ушли через «Завершить» с остатком — если это можно учесть; иначе хотя бы факт роста due).

### Перформанс (7 дней)

- доля «помню» отдельно по новым и по повторам;
- again rate overall;
- сколько ответов вернули карточку на `interval = 1`;
- again rate по mature (`interval ≥ 21` до ответа).

Ориентиры для статуса (не жёсткие пороги продукта, а правило подсказки):

- повторы ≥ 85–90% «помню», due не растёт → можно усилить;
- again по повторам > 20% или due растёт несколько дней → снизить;
- иначе → оставить.

### Статус нагрузки

Один вывод: **снизить / оставить / усилить**, с кратким советом по лимиту новых (например «15 → 10»). В первой версии совет текстовый, лимит меняется вручную в коде/настройке позже — автосмена лимита не нужна.

### Не входит в сводку (пока)

Тепловые карты на год, FSRS-калибровка, очки/стрики ради стриков, разбивка по всем темам, сравнение с Anki Desktop.
