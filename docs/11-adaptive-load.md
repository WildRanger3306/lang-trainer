# Адаптивная нагрузка

Статус: **реализовано** (MVP авто с гистерезисом).  
Сводка пишет совет в `load_advice_days`; при том же **lower**/**raise** **3 календарных дня** подряд меняет `user_load_limits.new_per_day`.

См. [4-decisions.md](4-decisions.md) §011. Бэклог: [6-iterations.md](6-iterations.md).

## Зачем

Лимит новых (EN 10 / FR 20) был константой. Due и again плывут. Цель — **двигать дневную квоту новых** по сигналам сводки, не трогая FSRS-интервалы.

Адаптируем **только `new_per_day`**, не FSRS и не due.

## Решение (MVP)

| Пункт | Выбор |
|-------|--------|
| Режим | **Авто с гистерезисом** |
| Рамки | EN **5–20** (default 10), FR **10–30** (default 20), шаг **5** |
| Гистерезис | тот же статус совета (**lower** / **raise**) **3 дня подряд** → тогда меняем лимит |
| Ручной UI (сводка / главная) | **не сейчас** → бэклог |
| Lock «не трогать авто» | **не сейчас** → бэклог |

Лимит **на пользователя × язык**. Константы = default при отсутствии строки.

Код: `app/load_limits.py`, `advise_load` / `refresh_adaptive_load` в `app/stats.py`. Триггер: главная, сводка, старт train / `/session`. Не чаще **1 изменения в календарный день** на язык. На сводке при смене: «авто: EN 10→5 (3 дн. подряд «lower»)».

## Сигналы совета (как сейчас)

| Сигнал | Снизить | Усилить |
|--------|---------|---------|
| отзывов за 7д | ≥ 20 | ≥ 20 |
| remember по повторам | &lt; 80% | ≥ 85% |
| again | &gt; 20% | ≤ 10% |
| due сегодня | ≥ max(40, 1.5× медиана ответов/день) | ≤ 15 |
| прочее | — | квота недобрана, есть «без прогресса» |

На min/max статуса lower/raise нет — совет становится **keep** («уже на минимуме/максимуме»).

## Хранение

| Таблица / поле | Смысл |
|----------------|--------|
| `user_load_limits` | `user_id`+`language`, `new_per_day`, `base_new_per_day`, `updated_via`, `last_change_on` |
| `load_advice_days` | дневной статус/suggested для гистерезиса |

## Что не трогаем

- FSRS / пачка оценки / preferred direction.
- EN и FR считаются **раздельно**.

## Бэклог после MVP авто

1. Ручная крутилка лимита (сначала сводка; главная — по желанию).
2. Lock «зафиксировать лимит» — авто не меняет, пока не снимут.
3. Тонкая настройка порогов `advise_load`, если срабатываний мало/много.
