# Адаптивная нагрузка

Статус: **решение зафиксировано**, реализация ещё нет.  
Сводка уже считает совет (`advise_load` в `app/stats.py`); автосмены лимита пока нет.

См. [4-decisions.md](4-decisions.md) §011. Бэклог: [6-iterations.md](6-iterations.md).

## Зачем

Лимит новых (EN 10 / FR 20) — константа. Due и again плывут. Цель — **двигать дневную квоту новых** по сигналам сводки, не ломая Anki-интервалы.

Адаптируем **только `new_per_day`**, не ease и не due.

## Решение (MVP)

| Пункт | Выбор |
|-------|--------|
| Режим | **Авто с гистерезисом** (вариант B), не полуручная кнопка первой |
| Рамки | EN **5–20** (default 10), FR **10–30** (default 20), шаг **5** |
| Гистерезис | тот же статус совета (**lower** / **raise**) **3 дня подряд** → тогда меняем лимит |
| Ручной UI (сводка / главная) | **не сейчас** → бэклог |
| Lock «не трогать авто» | **не сейчас** → бэклог |

Лимит **на пользователя × язык**. Константы = default при отсутствии строки.

Ядро: переиспользовать `advise_load()` (не второй алгоритм). Не чаще **1 изменения в календарный день** на язык. Не поднимать, если due уже в зоне «снизить».

Лог на сводке (желательно в MVP): «авто: FR 20→15 (again …, 3 дня lower)».

## Сигналы совета (как сейчас)

| Сигнал | Снизить | Усилить |
|--------|---------|---------|
| отзывов за 7д | ≥ 20 | ≥ 20 |
| remember по повторам | &lt; 80% | ≥ 85% |
| again | &gt; 20% | ≤ 10% |
| due сегодня | ≥ max(40, 1.5× медиана ответов/день) | ≤ 15 |
| прочее | — | квота недобрана, есть «без прогресса» |

## Хранение (при реализации)

| Поле | Смысл |
|------|--------|
| `user_id` + `language` | ключ |
| `new_per_day` | действующая квота |
| `base_new_per_day` | якорь (EN 10 / FR 20) |
| `updated_at` / `updated_via` | `auto` (позже `manual`) |
| история статусов совета | для гистерезиса 3д (или вычислять из прошлых дней) |

## Что не трогаем

- Интервалы / ease Anki, пачка оценки, preferred direction.
- EN и FR считаются **раздельно**.

## Бэклог после MVP авто

1. Ручная крутилка лимита (сначала сводка; главная — по желанию).
2. Lock «зафиксировать лимит» — авто не меняет, пока не снимут.
3. Тонкая настройка порогов `advise_load`, если срабатываний мало/много.
