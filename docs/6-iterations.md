# Итерации

Требования описывают продукт целиком. Здесь — срез, который можно закончить и пощупать.

Новые хотелки не правят [2-requirements.md](2-requirements.md), а попадают в бэклог следующей волны (или в [3-constraints.md](3-constraints.md), если это «не делаем»).

## Готово

**I1. Словарь в БД** — 92 единицы WL1 в Postgres (Docker), все с меткой Starlight 6. Проверка: `db/check.sql`.

**I2. Набор сессии** — фильтр + очередь Anki (due + новые). CLI: `scripts/pick_session.py`, JSON: `GET /session`.

**I3. Тренировка** — фильтр → карточка (переворот, помню / не помню) → due/интервал в БД. Вёрстка адаптивная.

**I4. Итог сессии** — число «помню» / «не помню», длительность, время.

**I5. Anki-повтор** — вместо `streak`: due, interval, ease; 15 новых/день на язык; Again в конец сессии.

**I6. Сводка** — лог `card_reviews`, экран `/stats` по языку: корпус / нагрузка / перформанс / совет по лимиту.

**I7. Оценка знаний** — отдельный режим триажа: Знаю (interval 7) / Сомневаюсь / Не знаю; не жжёт квоту новых.

**I8. Лимиты и направления** — EN 10 / FR 20 новых в день; приоритет RU→EN для английского, FR→RU для французского.

**I9. Многопользовательский режим** — вход логин/пароль; общий словарь; `card_progress` / `card_reviews` на пользователя; создание юзеров скриптом.

**I10. FSRS** — train: 4 кнопки; py-fsrs; конвертация progress; assess без изменений.

**I11. Адаптивная нагрузка** — autoload §011.

**I12. Сводка v2** — под FSRS/autoload: Сегодня / Autoload / Качество / Нагрузка / Корпус / Горизонт ([14-stats.md](14-stats.md)).

**I13. Home coach** — мотивирующий баннер на главной ([13-home-coach.md](13-home-coach.md)).
