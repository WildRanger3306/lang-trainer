# Итерации

Требования описывают продукт целиком. Здесь — срез, который можно закончить и пощупать.

Новые хотелки не правят [2-requirements.md](2-requirements.md), а попадают в бэклог следующей волны (или в [3-constraints.md](3-constraints.md), если это «не делаем»).

## Готово

**I1. Словарь в БД** — 92 единицы WL1 в Postgres (Docker), все с меткой Starlight 6. Проверка: `db/check.sql`.

**I2. Набор сессии** — фильтр + очередь Anki (due + новые). CLI: `scripts/pick_session.py`, JSON: `GET /session`.

**I3. Тренировка** — фильтр → карточка (переворот, помню / не помню) → due/интервал в БД. Вёрстка адаптивная.

**I4. Итог сессии** — число «помню» / «не помню», длительность, время.

**I5. Anki-повтор** — вместо `streak`: due, interval, ease; 15 новых/день на язык; Again в конец сессии.

**I6. Сводка** — лог `card_reviews`, экран `/stats` по языку: корпус / нагрузка / перформанс / совет по лимиту.

**I7. Оценка знаний** — отдельный режим триажа: Знаю (interval 7) / Сомневаюсь / Не знаю; не жжёт квоту новых.

**I8. Лимиты и направления** — EN 10 / FR 20 новых в день; приоритет RU→EN для английского, FR→RU для французского.

**I9. Многопользовательский режим** — вход логин/пароль; общий словарь; `card_progress` / `card_reviews` на пользователя; создание юзеров скриптом.

**I10. FSRS** — train: 4 кнопки; py-fsrs; конвертация progress; assess без изменений.

**I11. Адаптивная нагрузка** — autoload §011.

**I12. Сводка v2** — под FSRS/autoload: Сегодня / Autoload / Качество / Нагрузка / Корпус / Горизонт ([14-stats.md](14-stats.md)).

**I13. Home coach** — мотивирующий баннер на главной ([13-home-coach.md](13-home-coach.md)).

**Ранжирование слов по CEFR** — идея, обсуждена 2026-09-26, не решено.

Факты: в `entries.level` есть enum `cefr_level` (A1–B2, C1+ нет), заполнен только у 144 неправильных глаголов (ENGLISH99, уровень выведен из частотности); у остальных 4061 EN и 1205 FR — `NULL`. `SessionFilter.levels` и условие в `_filter_clause` есть, в UI нет. Новые слова сейчас берутся **случайно** внутри фильтра. Около 35% EN-записей (1476 из 4205) — из нескольких слов (фразы, фразовые глаголы), готовые списки CEFR их не покрывают.

Что даст (по убыванию пользы): (1) порядок новых слов «частые и лёгкие сначала», особенно внутри темы; (2) умная оценка знаний — начинать с A1–A2, пропускать уровни, где почти всё знаете, либо брать слова у границы словаря (как тест на размер лексики); (3) плашка «Уровень» в фильтре (чипы A1–B2 с числами, как «Части речи»); (4) сводка «знаю 62% A2, 15% B1».

Источники уровня: частотность (`wordfreq`, есть en и fr; бесплатно, офлайн, но слабо для многозначных слов, нет фраз) / готовые списки CEFR-J, Oxford 3000/5000 (уровни выверены, лицензии проверить, для FR хуже, фраз нет) / оценка моделью по слову, части речи и переводу (покрывает фразы, стоит денег, нужна проверка) / учебник как уровень (слишком грубо). Проверять любой метод на 144 глаголах с известным уровнем.

Предпочтительно: гибрид — частотность для одиночных слов, модель для фраз и сомнительных случаев. Хранить `level` + `level_source` (`freq` / `llm` / `manual`) + `freq_zipf` (порядок внутри уровня). Заполнение — скриптом по образцу `fill_en_transcriptions.py`; канон — JSON (поле `level` там уже есть), поэтому писать и в JSON, и проверить, обновляет ли `load_entries.py` `level` при слиянии.

Открытые вопросы: что первым — порядок новых (1), фильтр по уровню (3) или умная оценка (2) (предлагалось начать с 1 и 3); порядок «лёгкие сначала» всегда или переключатель «случайно / от частых к редким»; согласны ли, что уровень фраз ставит модель «на глаз».

**Раздельные фильтры train / assess** — сейчас один сохранённый фильтр на язык и для тренировки, и для оценки. Идея: отдельные наборы (учебник/темы) для режима оценки и для тренировки — например, триажить `sl7_m1`, а due гонять шире (или наоборот).

Варианты (обсуждено 2026-09-26, не решено):
1. **Два независимых фильтра** — на странице фильтров сегмент «Тренировка | Оценка», у каждого режима свой сохранённый выбор.
2. **Один фильтр + «оценивать другое»** — оценка по умолчанию использует фильтр тренировки; переключатель открывает второй, отдельный (пусто = как в тренировке). Предпочтительный: в обычные дни ничего лишнего, исключения вроде «оцениваю `bridge_sl6`, тренирую `sl7_m1`» — одним переключателем.
3. **Режим на каждом учебнике/теме** — «выкл / тренировка / оценка / оба» у карточки-учебника и чипа; всё на одном экране, но тяжело для телефона.

Открытый вопрос: слова, оценённые вне фильтра тренировки, получают сроки (7 дн / завтра), но повторы отбираются по фильтру тренировки, поэтому в очередь не попадают, пока пул не добавлен. Варианты — подсказка на главной («N слов из оценки вне фильтра») с кнопкой «добавить» (предпочтительно) или автоматически включать оценённые слова в тренировку (меняет смысл фильтра). Заодно подпись на главной «Оценка: до N карточек без прогресса» должна считаться по фильтру оценки. Технически: колонка `purpose` (или второй набор полей) в `user_language_filters`, страница фильтров, `/assess/start`, главная.
