# Решения

Одно решение — одна запись. Меняется поведение — [2-requirements.md](2-requirements.md). Меняется срез — [6-iterations.md](6-iterations.md).

## 001. Словарь в Postgres в Docker

- **Контекст.** I1: единицы из JSON должны лежать в БД, отбор по языку и меткам. Один пользователь, локально.
- **Варианты.** SQLite в файле; Postgres на хосте; Postgres в Docker.
- **Решение.** PostgreSQL в Docker Compose, данные в volume. Схема — `db/schema.sql`, загрузка JSON — `scripts/load_entries.py`.
- **Следствие.** Нужен Docker. С хоста порт **5433** (5432 на машине уже занят). Смена схемы на пустой базе: `docker compose down -v` и снова `up`.

## 002. FastAPI и HTML для прототипа

- **Контекст.** Три экрана, один пользователь, словарь уже в Postgres. Нужно быстро дойти до тренировки.
- **Варианты.** FastAPI + HTML/CSS и немного JS; SPA (React/Vue) + API; Next.js одним репозиторием.
- **Решение.** Один процесс FastAPI: HTML (Jinja) и чуть JS на переворот карточки. I2 — JSON/CLI без экранов. Состояние сессии на сервере, не в `localStorage`. Вёрстка адаптивная (телефон и компьютер), отдельного мобильного приложения нет.
- **Следствие.** Стек Python (как загрузчик JSON). Отдельного фронтенд-бандла в MVP нет.

## 003. Весь стек в Docker Compose

- **Контекст.** Postgres уже в Compose, приложение крутилось через `uvicorn` на хосте.
- **Решение.** Сервисы `db` и `app`. `docker compose up --build` поднимает базу, накатывает миграцию, при пустой таблице заливает WL1 и стартует FastAPI на порту 8000. Внутри сети приложение ходит в `db:5432`.
- **Следствие.** Python на хосте нужен только для тестов. Повторный `up` словарь не затирает.

## 004. Род французских существительных

- **Контекст.** В L'oiseau bleu существительные помечены `m` / `f` (иногда `m pl`). Нужно учить род без отдельного режима.
- **Варианты.** Поле `gender`; артикль в `form`; отдельная карточка «какой род?»; показ `le`/`la` только в UI.
- **Решение.** Необязательное поле `gender`: `m` | `f` | пусто. Артикль в `form`/БД не кладём. На карточке (display): для FR noun с родом — `le`/`la`/`les` перед формой на FR→RU (лицо) и на обороте RU→FR; `m`/`f` временно остаются в hint. Elision `l'` — позже. Квиз по роду — позже.
- **Следствие.** Английский и не-существительные без рода/артикля. Пары `ami`/`amie` — две единицы. Детали: [9-fr-articles.md](9-fr-articles.md).

## 005. Повтор как упрощённый Anki

- **Контекст.** Взвешивание по `streak` плохо держит большой словарь: выученное всё равно всплывает, нет «очереди на сегодня».
- **Варианты.** Оставить веса; полный SM-2/FSRS с 4 кнопками; упрощённый Anki на Again/Good.
- **Решение.** Due + интервалы × ease (старт 2.5); сессия = все due + новые; «Не помню» — в конец сессии и due завтра, ease −0.2. Лимиты новых: EN 10 / FR 20 (§008). Описание: [10-anki.md](10-anki.md).
- **Следствие.** Длина сессии плавает. Пропуск дня копит due. Старый `streak` сброшен.

## 006. Сводка для регулировки нагрузки

- **Контекст.** Anki-очередь без цифр не отвечает: пора ли поднять 15 новых или снизить.
- **Варианты.** Только снимок `card_progress`; полный дашборд; короткий экран + лог ответов.
- **Решение.** Экран «Сводка» по языку: корпус / нагрузка / перформанс / статус. Лог `card_review` на каждый ответ. Совет по лимиту — текст, без автосмены.
- **Следствие.** Нужна I6. Без лога again rate за неделю не посчитать.

## 007. Оценка знаний отдельно от тренировки

- **Контекст.** Корпус учебников уже частично известен; горизонт и квота 15 считают всё «новым».
- **Варианты.** Кнопка «Уже знаю» в обычной сессии; отдельный режим триажа; импорт «known» списком.
- **Решение.** Режим «Оценка знаний»: пачка до 40 без прогресса; Знаю → interval 7; Сомневаюсь/Не знаю → due завтра. Ввод через оценку не входит в дневной лимит новых (`introduced_via` / `source = assess`).
- **Следствие.** Ложные «Знаю» вернутся через неделю. Перформанс сводки считает только `source = train`.

## 008. Разные лимиты и приоритет направления

- **Контекст.** Школа: EN уже «обычный» → углублёнка; FR почти с нуля. Один лимит 15 и 50/50 направлений не оптимальны.
- **Варианты.** Один лимит; UI-настройка; константы в коде по языку + bias направления.
- **Решение.** `NEW_PER_DAY_BY_LANGUAGE`: EN 10, FR 20. В due/новых/оценке сначала предпочтительное направление (EN: RU→EN, FR: FR→RU), второе следом. Default-якорь; дальше см. §011 (адаптивная нагрузка).
- **Следствие.** Сводка и фильтр показывают лимит выбранного языка.

## 009. Уникальность единицы в БД, JSON — сырьё

- **Контекст.** Wordlist’ы разных классов/лет повторяют лексемы; две строки в БД → лишние карточки.
- **Варианты.** Чистить JSON; UNIQUE в БД; merge при загрузке.
- **Решение.** UNIQUE `(language, lower(form), part_of_speech)`. JSON не правим как канон дедупа. `load_entries --append` и полная загрузка делают upsert: сливают переводы и метки учебников. Разово — `scripts/dedupe_entries.py`.
- **Следствие.** Фильтр по учебнику видит одну единицу с несколькими `entry_textbooks`.

## 010. Несколько пользователей, общий словарь

- **Контекст.** Семья / несколько учеников на одном инстансе; прогресс нельзя смешивать.
- **Варианты.** Один пользователь; публичная регистрация; логин/пароль + юзеры скриптом.
- **Решение.** Таблица `users` (login + password_hash). Вход `/login`. Прогресс и отзывы с `user_id`. Словарь общий. Саморегистрации и ролей нет. Миграция: существующий прогресс → первому созданному пользователю.
- **Следствие.** I9. Все экраны тренировки только после авторизации.

## 011. Адаптивная нагрузка (new_per_day)

- **Контекст.** Константы EN 10 / FR 20 не учитывают тяжёлую/лёгкую неделю; сводка уже советует lower/keep/raise, но лимит не меняет.
- **Варианты.** Только текстовый совет; кнопка «применить»; авто каждый день; авто с гистерезисом.
- **Решение.** Авто по `advise_load`, лимит **на user × language**. Рамки: EN 5–20, FR 10–30, шаг 5. Менять только если тот же статус (**lower**/**raise**) **3 дня подряд**. Ручной UI лимита и lock «не трогать авто» — **не в MVP**, в бэклог. Детали: [11-adaptive-load.md](11-adaptive-load.md).
- **Следствие.** Таблицы `user_load_limits` и `load_advice_days`; квота через `get_new_per_day`. §006/§008: default — якорь.

## 012. Переход на FSRS

- **Контекст.** Упрощённый Again/Good (interval × ease) грубее современной модели памяти; хотим FSRS.
- **Варианты.** Оставить Anki-lite; 2 кнопки→Again/Good; полный FSRS с 4 кнопками.
- **Решение.** FSRS через `fsrs` (py-fsrs). Train: **Снова / Трудно / Хорошо / Легко**. Retention **90%**, fuzz **вкл**, due в **днях** (минуты округлять). «Снова» → конец сессии + due. Assess **без** FSRS (как сейчас 7/1/1). Веса — **дефолт на инстанс**. Прогресс: **грубая конвертация** interval/ease → S/D. Optimizer — бэклог. Детали: [12-fsrs.md](12-fsrs.md).
- **Следствие.** Миграция схемы `card_progress` / лога отзывов; UI 4 кнопок; снять FSRS из «не строим» в constraints. Адаптивная нагрузка (§011) остаётся отдельным рычагом.

## 013. Сводка под FSRS и autoload

- **Контекст.** Сводка звала «менять лимит вручную» и мерила «помню/again»; после §011/§012 это устарело.
- **Решение.** Экран `/stats`: блоки **Сегодня → Autoload → Качество (4 рейтинга) → Нагрузка → Корпус → Горизонт**. Алгоритм `advise_load` без смены. Детали: [14-stats.md](14-stats.md). Home coach на главной — отдельно, proposal: [13-home-coach.md](13-home-coach.md).
- **Следствие.** UI сводки объясняет авто, не просит крутить лимит.
